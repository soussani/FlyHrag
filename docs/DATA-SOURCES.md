## Honest limitations

- No provider in this integration resolves an arbitrary airline number/date to an official schedule, registration, gate or live status. Entry falls back to your ticket/manual information.
- Callsign, ICAO24, registration, model and commercial number are different fields. An aircraft association requires a user-supplied address and evidence. FlyHrag cannot independently verify that evidence.
- Recent aircraft observations are under two minutes old. Older/future timestamps are stale. Aircraft motion never automatically overwrites a flight record's status.
- Actual takeoff/landing, boarding and gate events are not inferred from schedule or aircraft position. User-entered departure/arrival times do not imply gate/runway specificity.
- No official delay feed or reliable prediction model. Timing differences are arithmetic from entered actual/estimated/scheduled times.
- No terminal navigation, minimum connection times, immigration rules, airport congestion estimates, satellite tiles or closed-app push.
- Aircraft change detection and full airline rotations are unavailable. Users can edit assignment manually; observed previous-day movements are not confirmed operating flights.
- The app uses a fixed public weather station list. Editing that list publishes those station codes; never add personal itinerary files or booking references.

## Storage and privacy

Only aircraft ICAO24 is sent to the selected public provider. Map tile requests expose viewed regions to OSM. No flight-number requests are made to external services. Airport search is local after initial download. Public Pages snapshots contain only directory/weather data, not local records. The service worker precaches the shell, lazy application chunks, icons and airport directory; Dexie stores flights, preferences, favorites, notifications, import logs and aircraft observations. No guaranteed automatic synchronization or durable iOS backup.

## Other providers evaluated and practical browser access

- **[adsb.fi open data](https://github.com/adsbfi/opendata)** is the default adapter. Public endpoints need no key and permit personal non-commercial use with attribution and a homepage link. Public limit: one request per second; FlyHrag uses five-minute opt-in polling and a sixty-second local cache, plus a shared 1.1-second request guard and persistent rate-limit backoff. It normalizes readsb feet/knots/ft-per-minute into the same SI position model as OpenSky. The provider's `now - seen_pos` supplies position time; missing coordinates or ground state stay unknown. No commercial use or resale is authorized.
- Direct tests with and without an Origin header on 23 September 2026 returned HTTP 200 JSON from adsb.fi, **without CORS permission**. FlyHrag cannot guarantee in-app live tracking from Pages and says so before the request. Its external [official map](https://globe.adsb.fi/) and user-imported matching JSON reports provide legitimate alternatives. Imported reports are labeled; no external status is inferred. These reports remain private and are never added to the Pages repository.
- **[ADSB.lol](https://www.adsb.lol/docs/open-data/api/)** makes its public API available under ODbL 1.0 with dynamic rate limits. It also returned no CORS header during a bounded probe, so no automatic fallback would solve the browser restriction. Not integrated or polled.
- **Airplanes.live** returned HTTP 403 during one bounded probe; not integrated and not retried to bypass access restrictions.
- **[AvioADSB](https://avioadsb.org/docs/api)** documents CC BY 4.0 public data, but its tested endpoint is a network-wide snapshot and returned same-origin browser restrictions. It was not integrated: FlyHrag avoids unnecessary global downloads and cannot assume CORS access.

No anonymous endpoint's technical availability is treated as permission to override provider terms. There are no CORS proxies, authenticated feeder-only endpoints, paid services, public aircraft watchlists, or published personal itineraries in this architecture.
